# 上下位机通信规范

> 上位机：Raspberry Pi（发送指令、接收数据）  
> 下位机：STM32（接收指令、执行动作、上报数据）  
> 物理层：UART, 115200-8N1

---

## 1. 帧协议

### 1.1 帧格式

```
┌───────┬──────┬──────┬──────────┬──────────┬──────┐
│ HEAD  │ TYPE │ LEN  │ DATA     │ CRC16    │ TAIL │
│ 2 Byte│ 1 B  │ 1 B  │ 0-250 B  │ 2 B      │ 1 B  │
│ AA 55 │      │      │          │          │ BB   │
└───────┴──────┴──────┴──────────┴──────────┴──────┘
```

**字段说明:**

| 字段 | 长度 | 值 | 说明 |
|------|------|----|------|
| HEAD | 2B | `0xAA 0x55` | 帧起始标志 |
| TYPE | 1B | 见 §2 | 帧类型 |
| LEN | 1B | 0-250 | DATA 段字节数，`LEN=0` 表示无数据 |
| DATA | N B | — | 数据负载，长度由 LEN 指定 |
| CRC16 | 2B | — | CRC16-CCITT，覆盖 `TYPE + LEN + DATA`，高位在前 |
| TAIL | 1B | `0xBB` | 帧结束标志 |

**最小帧长度：** 7 字节（LEN=0 时）  
**最大帧长度：** 261 字节（LEN=250 时）

### 1.2 CRC16-CCITT 计算

- 多项式: `0x1021`
- 初值: `0xFFFF`
- 覆盖范围: `TYPE` + `LEN` + `DATA`（不包括 HEAD 和 TAIL）
- 字节序: 高位在前（大端）

Python 查表法实现（与下位机 `crc16_table` 完全一致）：

```python
_CRC_TABLE = [...]  # 256 元素查表
def calc_crc(data: bytes) -> int:
    crc = 0xFFFF
    for b in data:
        crc = ((crc << 8) ^ _CRC_TABLE[((crc >> 8) ^ b) & 0xFF]) & 0xFFFF
    return crc
```

## 2. 帧类型定义

### 2.1 类型总表

| 类型码 | 方向 | 名称 | DATA 长度 | 说明 |
|:------:|------|------|:---------:|------|
| `0x01` | STM32 → Pi | `HEARTBEAT` | 4B | 心率+血氧数据上报 |
| `0x03` | STM32 → Pi | `SENSOR_STATUS` | 2B | 传感器状态 |
| `0x04` | STM32 → Pi | `ACK` | 0B | 指令执行成功应答 |
| `0x05` | STM32 → Pi | `NAK` | 0B | 指令执行失败应答 |
| `0x10` | Pi → STM32 | `OLED` | 1-250B | OLED 控制（含子命令） |
| `0x11` | Pi → STM32 | `SERVO` | 3B | 舵机控制 |
| `0x12` | Pi → STM32 | `QUERY_SENSOR` | 0B | 查询传感器（触发立即上报） |
| `0x13` | Pi → STM32 | `CONFIG` | 4B | 配置参数 |

---

### 2.2 各帧详细格式

#### HEARTBEAT (0x01) — STM32 → 树莓派

定时上报或响应 QUERY_SENSOR 时发送。

```
DATA: [HR_VAL] [HR_OK] [O2_VAL] [O2_OK]
       1B      1B      1B       1B
```

| 偏移 | 名称 | 类型 | 说明 |
|:----:|------|------|------|
| 0 | HR_VAL | uint8 | 心率值 (bpm)，0 表示无效 |
| 1 | HR_OK | uint8 | `1`=有效, `0`=无效 |
| 2 | O2_VAL | uint8 | 血氧饱和度 (%)，0 表示无效 |
| 3 | O2_OK | uint8 | `1`=有效, `0`=无效 |

**上位机解析示例：**
```
AA 55 01 04 48 01 62 01 CRC_H CRC_L BB
         │  │  │  │
         │  │  │  └─ O2_OK = 1 (有效)
         │  │  └──── O2    = 98 (%)
         │  └─────── HR_OK = 1 (有效)
         └───────── HR    = 72 (bpm)
```

#### SENSOR_STATUS (0x03) — STM32 → 树莓派

```
DATA: [STATUS] [ERR_CODE]
       1B       1B
```

| 偏移 | 名称 | 类型 | 说明 |
|:----:|------|------|------|
| 0 | STATUS | uint8 | `0`=离线 `1`=在线 `2`=错误 |
| 1 | ERR_CODE | uint8 | 错误码，STATUS=2 时有效 |

#### ACK (0x04) — STM32 → 树莓派

```
DATA: 无（LEN=0）
```

下位机成功执行指令后回复。上位机收到 ACK 确认指令已生效。

#### NAK (0x05) — STM32 → 树莓派

```
DATA: 无（LEN=0）
```

下位机执行指令失败时回复（如参数错误、硬件故障等）。

---

#### OLED (0x10) — 树莓派 → STM32

通过子命令区分操作类型：

```
DATA: [CMD] [子命令参数...]
       1B
```

| CMD | 名称 | DATA 格式 |
|:---:|------|-----------|
| `0x00` | 显示表情 | `[CMD=0x00] [CONFIDENCE] [NAME_LEN] [NAME_UTF8...]` |
| `0x01` | 显示文本 | `[CMD=0x01] [X] [Y] [TEXT_LEN] [TEXT_UTF8...]` |
| `0x02` | 清屏 | `[CMD=0x02]` |

**子命令 0x00 — 显示表情：**

```
DATA: [00] [CONFIDENCE] [NAME_LEN] [NAME...]
       1B   1B           1B          N B
```

| 偏移 | 名称 | 说明 |
|:----:|------|------|
| 0 | CMD | `0x00` |
| 1 | CONFIDENCE | 置信度 0-100 |
| 2 | NAME_LEN | 表情名称 UTF-8 字节长度 |
| 3~ | NAME | 表情名称 UTF-8 字符串（如 "开心"、"悲伤"） |

**子命令 0x01 — 显示文本：**

```
DATA: [01] [X] [Y] [TEXT_LEN] [TEXT...]
       1B   1B  1B  1B          N B
```

| 偏移 | 名称 | 说明 |
|:----:|------|------|
| 0 | CMD | `0x01` |
| 1 | X | 显示 X 坐标 (像素) |
| 2 | Y | 显示 Y 坐标 (像素) |
| 3 | TEXT_LEN | 文本 UTF-8 字节长度 |
| 4~ | TEXT | 文本 UTF-8 字符串 |

**子命令 0x02 — 清屏：**

```
DATA: [02]
       1B
```

**上位机发送示例：**
```
AA 55 10 09 00 55 06 E5 BC 80 E5 BF 83 CRC_H CRC_L BB
         │  │  │  └──────┬──────┘
         │  │  │         └─ "开心" (UTF-8, 6字节)
         │  │  └─────────── NAME_LEN = 6
         │  └────────────── CONFIDENCE = 85
         └───────────────── CMD = 0x00 (显示表情)
```

#### SERVO (0x11) — 树莓派 → STM32

```
DATA: [SERVO_ID] [ANGLE] [SPEED]
       1B         1B      1B
```

| 偏移 | 名称 | 范围 | 说明 |
|:----:|------|:----:|------|
| 0 | SERVO_ID | 0-1 | `0`=点头舵机, `1`=摇头舵机 |
| 1 | ANGLE | 0-180 | 目标角度（度） |
| 2 | SPEED | 1-10 | 转动速度 |

**上位机发送示例：**
```
AA 55 11 03 00 5A 05 CRC_H CRC_L BB
         │  │  │
         │  │  └─ SPEED = 5
         │  └──── ANGLE = 90
         └────── SERVO_ID = 0 (点头)
```

#### QUERY_SENSOR (0x12) — 树莓派 → STM32

```
DATA: 无（LEN=0）
```

上位机主动请求传感器数据。下位机收到后应立即上报一次 `HEARTBEAT` + `SENSOR_STATUS`，然后回复 `ACK`。

#### CONFIG (0x13) — 树莓派 → STM32

```
DATA: [INTERVAL_MS_4B]
        4B (大端)
```

| 偏移 | 名称 | 说明 |
|:----:|------|------|
| 0-3 | INTERVAL_MS | uint32 大端，健康数据上报间隔（毫秒） |

**示例：** `00 00 07 D0` = 2000ms = 每 2 秒上报一次

## 3. 通信流程

### 3.1 正常交互流程

```
树莓派                              STM32
   │                                  │
   │──── QUERY_SENSOR (0x12) ────────→│  (主动查询)
   │                                  │
   │←── HEARTBEAT (0x01) ────────────│  (立即上报健康数据)
   │←── SENSOR_STATUS (0x03) ────────│  (立即上报传感器状态)
   │←── ACK (0x04) ─────────────────│  (确认收到查询)
   │                                  │
   │                                  │  (1 秒后)
   │←── HEARTBEAT (0x01) ────────────│  (定时上报)
   │←── SENSOR_STATUS (0x03) ────────│  (定时上报)
   │                                  │
   │──── OLED (0x10) ────────────────→│  (显示表情指令)
   │←── ACK (0x04) ─────────────────│  (确认 OLED 已显示)
   │                                  │
   │──── SERVO (0x11) ───────────────→│  (舵机控制指令)
   │←── ACK (0x04) ─────────────────│  (确认舵机已动作)
   │                                  │
```

### 3.2 下位机行为规范

**上电初始化后：**
1. 依次执行硬件自检（LED、OLED、舵机、MAX30102），耗时约 10 秒
2. 进入主循环后，**每 1 秒**自动上报 `HEARTBEAT` + `SENSOR_STATUS`
3. 主循环中**每帧必须调用** `Parser_Process()`，无论传感器状态如何
4. `Handler_Tick()` 必须在主循环中周期性调用

**收到指令时：**
- `QUERY_SENSOR` → 立即上报 `HEARTBEAT` + `SENSOR_STATUS`，再回复 `ACK`
- `OLED` → 执行对应显示操作 → 回复 `ACK` / `NAK`
- `SERVO` → 驱动舵机 → 回复 `ACK` / `NAK`
- `CONFIG` → 更新参数 → 回复 `ACK` / `NAK`
- 未知类型 → 回复 `NAK`

**数据上报要求：**
- `HEARTBEAT` 中 HR_OK/O2_OK 标记数据有效性
- 传感器未就绪时上报 `HR_VAL=0, HR_OK=0, O2_VAL=0, O2_OK=0`
- `SENSOR_STATUS` 中的 STATUS 反映传感器整体状态

### 3.3 回显规则

**连通性测试阶段**下位机可对每个接收字节原样回显（用于调试）。
**正式运行时必须关闭回显**，避免以下问题：
- ISR 中阻塞式发送拖慢中断响应
- 回显数据被上位机接收后干扰帧解析

## 4. 粘包处理

串口是流式协议，一帧数据可能分多次到达，或多帧数据连续到达。下位机解析策略：

```
Parser 状态机:
  IDLE ──0xAA──→ HEAD_2 ──0x55──→ HEADER (收 TYPE+LEN)
    ↑                              │
    └──── 刷新重置 ←─── 错误 ─────┘
                                       │
                                  DATA (收 DATA+CRC+TAIL)
                                       │
                                  ┌────┴────┐
                                  ↓         ↓
                              校验成功    校验失败
                               → 回调     → 丢弃+错误计数
```

**关键规则：**
- 收到 `0xAA` 进入帧头等待状态
- 收到 `0xAA 0x55` 后继续收 TYPE + LEN
- 从 LEN 字段计算帧总长度：`2 + 1 + 1 + LEN + 2 + 1`
- 收齐后验证 CRC 和 TAIL
- 校验通过则回调上层处理；失败则丢弃并推进一个字节
- 任何阶段超时（建议 500ms 无数据）则重置状态机

---

## 5. 错误处理

| 异常场景 | 下位机行为 |
|---------|-----------|
| CRC 校验失败 | 丢弃帧，递增错误计数 |
| 帧头错误 (`≠AA55`) | 丢弃该字节，继续搜索 AA |
| 帧尾错误 (`≠BB`) | 丢弃帧，递增错误计数 |
| LEN 超限 (>250) | 丢弃帧，重置状态机 |
| 未知 TYPE | 回复 `NAK` |
| 执行失败（如舵机角度越界） | 回复 `NAK` |

| 配置心跳间隔 2000ms | `0x13` | `00 00 07 D0` | 11B |
| 健康数据 HR=72 SpO2=98 | `0x01` | `48 01 62 01` | 11B |
| 传感器状态 online | `0x03` | `01 00` | 9B |

| NAK | `0x05` | (空) | 7B |

> `0x01`、`0x03`、`0x04`、`0x05` 为下位机需要发送的回复。
